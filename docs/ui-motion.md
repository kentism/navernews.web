# UI 모션과 로딩 상태

## 원칙

기존 모노톤, FastAPI/Jinja2/vanilla JavaScript 구조를 유지한다. `static/js/ui_motion.js`가 표시 효과와 타이머를 담당하며, 검색 요청/응답/저장/복사 형식은 기존 모듈에서 처리한다. 추가 라이브러리, 환경변수, 배포 설정 변경은 없다.

- 응답을 기다리는 동안만 로딩을 표시한다. 애니메이션이 끝나기를 기다려 결과를 늦게 표시하지 않는다.
- 큰 이동, 장식용 이미지, 무거운 블러, 기사별 긴 순차 등장 효과는 사용하지 않는다.
- 비활성 검색 탭에는 스켈레톤 표시 타이머를 남기지 않고, 로딩 반복 효과는 활성 탭에서만 실행한다.
- 클리핑 편집기는 탭 전환 시 재생성하지 않는다. 입력 내용과 편집기 인스턴스를 유지한다.

## 상태별 표현

최초 검색/재시도는 검색어 제목과 상태 문구를 즉시 표시한다. `대기`는 시계, 실제 `검색 중`은 회전 아이콘으로 구분한다. 활성 탭이 150ms 이상 기다릴 때만 기사 형태의 스켈레톤 3개를 표시한다. 완료/실패/닫기/탭 이동 시 표시 타이머를 취소하므로 빠른 결과 뒤에 로딩이 다시 나타나지 않는다.

새로고침과 기간 조회는 기존 결과를 지우지 않는다. 버튼의 아이콘/`aria-busy`와 결과 영역의 `aria-busy`로 진행을 알린다. 실패하면 기존 결과와 재시도 경로를 유지하며, 성공하면 즉시 결과를 갱신한다.

탭 본문은 150ms, 검색 결과는 180ms, 열린 탭 메뉴는 120ms 이내의 투명도/작은 이동 효과를 사용한다. 이미 선택된 탭을 다시 누르면 본문 효과를 반복하지 않는다. 추가 조회는 화면에 보이는 새 기사에만 적용하고 기존 기사를 재등장시키지 않는다.

활성 탭 밑줄은 이동/크기 변화에 `transform`을 사용한다. 검색 탭 스크롤 영역 밖으로 넘어가지 않도록 제한하고, 창/탭 영역 크기 변경과 가로 스크롤 때 위치를 갱신한다. 탭 자동 이동은 가로 스크롤에만 적용하여 문서 전체를 자동 스크롤하지 않는다.

전체 검색 진행 막대는 실제 처리 건수만 반영한다. 의미 정보는 원래 `<progress>`에 유지하고 표시 막대만 `scaleX`로 보간한다. 완료 후에도 막대를 유지해 상태 문구가 옆으로 갑자기 밀리지 않도록 한다. 가짜 진행률이나 성공처럼 보이는 실패 상태를 만들지 않는다.

클리핑 추가/복사에 성공한 경우에만 기존 아이콘을 800ms 동안 체크로 바꾼다. 버튼 문구와 크기는 바꾸지 않고 토스트도 유지한다. 중복 기사/복사 실패에는 성공 표시를 새로 실행하지 않는다.

## 접근성과 수명 관리

`prefers-reduced-motion: reduce`에서는 CSS 반복 효과와 JavaScript 등장/밑줄/진행률 애니메이션을 실행하지 않는다. 실행 도중 설정이 바뀌어도 진행 중인 JavaScript 효과를 취소한다. 스크롤 버튼과 탭 자동 가로 이동도 즉시 이동으로 전환한다. 정적 상태/오류/완료 아이콘과 실제 진행률은 계속 제공한다.

표시 효과는 Web Animations API를 사용할 수 있을 때만 실행하며 미지원 환경에서는 즉시 표시한다. 빠른 재실행은 이전 효과를 취소하고 취소 Promise를 처리한다. 등장 효과는 DOM을 교체하거나 클릭을 막지 않는다. 클리핑 내용이나 저장 키를 변경하지 않는다.

## 검증

Node 테스트는 지연 로딩의 취소, 대기/실행 구분, 숨긴/닫힌 탭, 모션 축소, 빠른 애니메이션 취소, 밑줄 범위, 진행/성공 아이콘 복원과 실제 진행률을 검증한다. 브라우저에서는 느린 검색/빠른 응답/실패/재시도/탭 연속 전환, 기존 결과와 편집기 보존, 모션 축소, 모바일/다크 모드를 확인한다. 외부 검색 요청은 샘플 응답으로 대체한다.
