# 검색 작업공간과 UI

## 홈 검색어 모음

- `navernews_home_keywords` localStorage 키에 최대 15개 검색어를 저장한다. 기존 8개 목록을 그대로 읽고 추가 입력을 허용하며, 클리핑 초안/최근 검색/알림 키와 분리한다.
- 처음 방문하거나 저장값이 손상된 경우에만 서버의 기본 검색어를 초기값으로 사용한다. 사용자가 모두 지운 빈 목록은 그대로 유지한다.
- 새 검색어 추가, 행 안에서 수정, 개별 검색/삭제, 전체 검색을 제공한다. 동일한 문자열의 중복과 300자 초과 입력을 거부한다.
- `전체 검색`은 최대 15개 검색어의 탭을 열고 첫 탭을 활성화한다. 최초 조회는 최대 3개씩 처리하며, 실패해도 다음 검색어를 계속 처리한다. 이미 정상 조회된 탭은 재사용하고, 이전에 실패한 탭은 조회한다. 처리 중 다시 전체 검색을 호출해도 같은 작업을 공유한다.
- 상단 상태줄은 처리 건수/전체 건수, 기존 탭 재사용, 실패, 닫힌 탭 제외를 구분한다. 완료 후 실패 검색어만 재시도하거나 상태줄을 닫을 수 있다. 대기 중인 탭을 닫으면 해당 탭은 조회하지 않는다.
- `검색 탭` 목록은 긴 검색어 전체와 대기/검색 중/실패 상태를 표시한다. 목록 안에서 이름을 검색해 이동할 수 있고 Esc/바깥 클릭으로 닫는다. 탭 생성/닫기/활성 상태와 함께 갱신한다. 홈/클리핑 탭은 검색 탭의 가로 스크롤과 분리해 항상 접근할 수 있도록 유지한다.
- 저장 실패는 홈 상태 문구로 표시한다. 다른 브라우저나 기기에는 목록이 공유되지 않는다. 새로운 환경변수는 필요하지 않다.
- 홈 검색은 저장된 검색어 자체로 실행한다. 상단 고급 필터는 상단 검색에만 적용한다. 접속 직후의 기본 검색어 자동 검색은 제거했다.

## 최근 검색과 문의

- 홈의 최근 검색 목록과 상단 검색창의 최근 검색 목록에서 각 항목의 삭제 아이콘으로 검색 기록을 삭제한다. 두 목록은 기존 `navernews_recent_keywords` 키를 공유하며 삭제 직후 함께 갱신된다. 마지막 항목을 삭제하면 홈에 빈 목록 안내를 표시한다.
- 삭제는 최근 검색 기록에만 적용한다. 저장 검색어, 열린 검색 탭, 작성 중인 클리핑은 변경하지 않는다. 브라우저 저장 실패 시 목록을 삭제한 것처럼 표시하지 않고 오류를 알린다.
- 공통 하단에 `사이트 문의 knh@kocsc.or.kr`을 표시한다. 이메일은 `mailto:` 링크이며 홈/검색/클리핑 탭에서 동일하게 표시한다.
- 최근 검색 삭제/문의 표시의 최초 반영 시에는 사용자 요청에 따라 별도 테스트 및 브라우저 검증을 실행하지 않았다.

## 로그인 화면

- 기존 큰 이모지, 둥근 카드와 그림자, 페이지 내부 스타일을 제거하고 공통 CSS와 Lucide 신문 아이콘을 사용한다. 360px 이내의 간결한 폼과 본문과 동일한 색상/6px 모서리의 입력창/버튼으로 정리했다.
- 비밀번호의 명시적 레이블, 자동완성(`current-password`), 한국어 오류 안내와 `aria-invalid`/`aria-describedby`를 제공한다. 오류 쿼리 문자열은 화면에 그대로 출력하지 않는다.
- `static/js/login.js`는 기존 `theme` 저장값에 따라 라이트/다크 테마만 적용한다. 저장소 접근이나 JavaScript가 실패해도 기본 라이트 화면의 로그인 폼은 정상적으로 제출된다. 로그인 화면에서는 추가 애니메이션이나 프레임워크를 사용하지 않는다.
- 하단에 `사이트 문의 knh@kocsc.or.kr` 메일 링크를 표시한다. 좁은 화면에서도 폼은 화면 너비를 넘지 않으며, 낮은 화면에서는 문서를 스크롤할 수 있다.
- `POST /login`, `password` 필드, 기존 기본 비밀번호, `APP_ACCESS_KEY` 환경변수와 인증 쿠키 설정은 변경하지 않는다. 새 환경변수나 배포 설정 변경은 필요 없다.
- 통합 테스트는 로그인 폼/레이블/오류 표시와 기존 비밀번호의 성공·실패 및 인증 쿠키 발급을 확인한다.

## 요청과 부하

일괄 검색의 동시 처리 상한은 `static/js/search_batch.js`의 `CONCURRENCY = 3`이며 저장/검색 상한 `LIMIT = 15`와 분리한다. 브라우저의 검색 대기열과 저장 목록이 같은 정규화/상한을 사용한다. 일괄 검색 중에는 자동 추가 페이지 조회를 잠시 보류한다. 사용자의 개별 검색/수동 추가 조회와 알림은 별도 흐름이므로 서버 전체의 요청 수를 항상 3개로 제한하는 전역 속도 제한은 아니다.

새 검색어 15개의 첫 페이지 조회에는 기본적으로 15회 외부 요청이 필요하다. 재시도, 추가 페이지, 기간 조회, 알림 감시는 별도 요청을 사용한다. 동시 처리 제한은 순간 부하를 완화하지만 외부 API 계정의 전체 호출 한도를 대체하지 않는다. 추가 환경변수나 배포 설정 변경은 없다.

## 검색 결과

검색 제목/보기 방식/실시간 알림/새로고침, 기간 도구, 기사 목록을 분리했다. 기사만 `.news-items` 안에 들어가며 2열 전환과 추가 조회는 이 영역에만 적용된다. 검색어별 기간 조회 실패 시 기존 결과를 보존한다.

시작일/종료일은 한국 시간 기준으로 어제~오늘을 초기값으로 제시한다. 입력만으로 조회하지 않으며 `기간 조회`로 확정한다. 종료일은 해당 날짜 전체를 포함하고, 빈 종료일은 오늘로 처리한다. 한도 도달 경고는 감추지 않는다. `최신순`은 기간 결과에서 일반 최신순 검색으로 돌아간다.

기사 선택 체크박스, 전체 선택, 선택 건수, 일괄 분류/클리핑 도구는 제거했다. 기사별 클리핑 메뉴는 기존 분류와 복사 형식을 그대로 사용한다.

제목이 잘렸을 가능성이 있는 지원 기사에는 수동 `제목 확인`을 제공한다. 원래 검색 제목을 유지하고, 확인 결과와 출처를 별도로 표시한다. 사용자가 체크한 경우에만 이후 클리핑에 확인 제목을 사용한다. 조회 제한/인증/실패 처리는 [뉴스 카드의 수동 제목 확인](article-title-confirmation.md)을 따른다.

## 화면 기준

- 흰색/중성 회색/검정 팔레트와 라이트/다크 모드를 유지한다. 전역 스타일의 중복과 사용하지 않는 랜딩 페이지 스타일을 정리했다.
- 상단 헤더를 압축하고 탭은 브라우저 너비를 사용한다. 읽기 영역만 제한하며 좁은 화면의 탭은 가로 탐색한다.
- 저장 목록은 스크롤 영역으로 두어 15개를 저장해도 추가 입력/저장 상태가 화면 아래로 과도하게 밀리지 않도록 한다.
- 반복 안내와 큰 배경 카드를 줄이고 도구 높이/간격을 통일했다. 클리핑 복사/다운로드 도구는 문서 위에, 접을 수 있는 알림 관리는 문서 아래에 둔다.
- 아이콘은 Lucide v0.468.0의 필요한 심볼만 `/static/icons.svg`에 포함한다. 별도 JS 라이브러리/CDN 연결은 필요 없다. 출처/권한은 `static/icons.LICENSE.txt`에 기록했다.
- 변경된 CSS/JS의 버전 쿼리로 이전 정적 파일 캐시와 새 템플릿의 혼용을 방지한다.
- 검색 대기/실행 상태, 지연 스켈레톤, 짧은 탭/결과 전환과 완료 피드백은 [UI 모션](ui-motion.md)의 원칙을 따른다. 실제 결과 표시나 클리핑 저장을 애니메이션 때문에 지연하지 않는다.

## 검증

검색어 정규화/15개 상한/기존 8개 목록 호환/중복/빈 목록/수정, 동시 처리 3개/진행률/부분 실패/재시도는 Node 단위 테스트로 검증한다. 템플릿 구조와 선택 기능 제거는 Python 통합 테스트로 검증한다. 브라우저에서는 15개 검색/재사용/실패 재시도/대기 탭 닫기/열린 탭 목록, 저장 후 새로고침, 기간/최신순 전환, 추가 조회, 1열/2열, 개별 클리핑/복사, 다크 모드와 모바일 가로 넘침을 확인한다. 검색 API는 샘플 응답으로 대체한다.
