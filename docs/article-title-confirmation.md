# 뉴스 카드의 수동 제목 확인

## 사용자 동작

- 최신순/기간 조회 결과의 모든 기사 카드에 `제목 확인` 버튼을 표시한다. 결과 상단에 `제목이 잘린 경우 ‘제목 확인’을 이용하세요.`를 한 번 안내한다. 말줄임표 유무로 버튼을 숨기지 않는다.
- 지원 URL과 유효한 제목이 없는 카드도 버튼은 표시한다. 클릭하면 원문 보기에서 확인하도록 안내하며, 서버 조회 요청은 보내지 않는다. 모든 카드에 버튼이 있다고 모든 사이트 조회를 허용하는 것은 아니다.
- 검색, 카드 노출, 스크롤, 마우스 올리기, 일반 클리핑은 원문 제목 조회를 실행하지 않는다. 사용자가 버튼을 눌렀을 때만 해당 기사를 조회한다.
- 원래 검색 제목은 항상 그대로 유지한다. 확인 결과는 제목 아래의 구분선 영역에 평문으로 표시하고, 실제 조회한 페이지에 따라 `네이버 기사`/`언론사 원문` 출처 링크를 제공한다.
- `확인한 제목을 클리핑에 사용` 체크박스는 기본적으로 꺼져 있다. 확인 후 선택한 경우에만 다음 클리핑에서 그 제목을 사용한다. 선택을 해제하면 검색 제목으로 돌아간다. 이미 작성한 클리핑이나 편집기의 수정 내용은 자동으로 바꾸지 않는다.
- 결과를 접어도 선택은 유지하며 버튼의 `확인 제목 사용` 문구로 표시한다. 같은 카드의 결과를 다시 펼치는 동작은 재조회하지 않는다. 새로고침/기간 재조회로 카드를 새로 만들면 선택은 초기화한다.
- 확인 중에는 해당 버튼만 비활성화하고 작은 회전 아이콘을 표시한다. 기존 검색/클리핑은 계속 사용할 수 있다. `추가 제목 없음`, `일치 확인 불가`, 실패/재시도는 카드 안에서 표시하며 반복 토스트나 전체 화면 로딩은 만들지 않는다.

## 제목 판정

공통 로직은 `services/article_titles.py`에 있다. 프로토타입도 같은 코드를 사용한다.

- 기사형 JSON-LD, Open Graph/Twitter 제목, headline 메타데이터, HTML 제목 요소를 읽는다. 이미지/광고/페이지 자바스크립트는 실행하지 않는다.
- 정규화 후 12자 이상인 검색 제목 접두부와 일치하는 더 긴 제목, 또는 같은 글자에 말줄임표/닫는 기호 차이만 있는 제목만 선택 가능하다. 끝에 말줄임표가 없는 잘린 제목도 비교한다. 서로 다른 확장 제목이 있으면 보류한다. 추측이나 AI 보완은 하지 않는다.
- 말줄임표 없는 검색 제목과 실제 기사 제목 요소가 정확히 일치하면, 더 긴 SEO용 메타 제목보다 그 일치를 우선한다. 다른 메타 제목이 있으면 브라우저 제목 태그의 부가 문구를 확장 제목으로 채택하지 않는다.
- 원문에도 말줄임표가 남거나 추가 제목이 없으면 `추가 제목 없음`으로 처리한다. 불일치/충돌 결과에는 제목 적용 선택을 제공하지 않는다.
- API 원본 제목, 확인한 제목, 사용자의 선택을 분리한다. 확인은 정확성 보조이며 제목의 완전성을 보증하지 않는다.

## 보안과 부하

- `POST /api/search/title-confirmation`은 기존 로그인 인증을 요구한다. 클라이언트의 임의 `url`/`title`은 사용하지 않는다.
- 서버가 검색 카드에 발급한 HMAC 서명 토큰만 받는다. 토큰은 서버가 확인한 제목과 지원 URL에 묶여 있고 30분 뒤 만료된다. 만료되면 검색 결과를 새로고침해야 한다. 기존 `NAVER_CLIENT_SECRET`에서 용도를 분리해 서명키를 만들며 새 환경변수는 필요 없다. 인증정보를 HTML/토큰에 넣지 않는다. 해당 비밀값이 없는 로컬 모의 환경에서는 프로세스 임시 키를 사용한다.
- Origin 헤더가 있으면 같은 출처인지 확인한다. HTTPS의 명시된 호스트만 허용하며, 리디렉션도 매번 재검증한다. 사설/루프백/링크 로컬/혼합 DNS를 거부하고 검증한 공개 IP에 직접 연결한다. 원래 도메인으로 TLS 인증서를 검증하며 프록시 환경변수는 사용하지 않는다.
- 프로세스당 동시에 서로 다른 기사 2건만 조회한다. 같은 URL/검색 제목의 진행 중 요청은 공유하며, 세 번째 별도 요청은 기다리는 작업을 쌓지 않고 재시도를 안내한다. 현재 Docker 기본 명령은 단일 프로세스다. 향후 worker/인스턴스를 늘리면 전체 한도는 별도로 설계해야 한다.
- 원문 조회는 전체 제한 시간 3초, 리디렉션 최대 2회, 입력/압축 해제 HTML 각각 최대 512KiB로 제한한다. gzip/deflate의 압축 해제도 크기를 제한하고 다른 인코딩은 실패 처리한다. 자동 재시도는 없다. OS DNS 작업이나 동기적인 제한 크기 HTML 파싱의 종료 시점까지 정확히 3초라고 보장하는 것은 아니다.
- 브라우저는 4.5초 뒤 응답 대기를 중단한다. 제거된 카드에는 늦게 도착한 결과를 반영하지 않는다. 동일 기사의 동시 브라우저 요청도 공유한다.
- 완료 결과의 서버 캐시/DB/자동 백업은 만들지 않는다. 응답은 `Cache-Control: no-store`이며 확인 상태는 현재 카드에만 둔다. 앱 종료 시 진행 중 작업을 취소한다.

## 운영과 이용 조건

배포 설정/의존성/기존 비밀번호는 변경하지 않는다. 지원 호스트 추가는 `ALLOWED_HOSTS`와 테스트를 함께 갱신한다. 단순한 언론사명 매핑 추가만으로 조회 호스트를 허용하지 않는다.

검색 API 결과와 확인 제목을 구분하고 원문 링크를 제공하지만, 이것이 약관 준수를 자동으로 보장하지는 않는다. 서비스 운영 시 [네이버 검색 API 이용 조건](https://developers.naver.com/notice/article/33400) 및 원문 사이트의 이용 조건을 별도로 확인해야 한다. 기능을 제거할 경우 라우터/템플릿 필터/JS 호출/스타일/테스트를 함께 제거한다. 기존 클리핑 문서와 저장 키는 유지한다.

## 검증

```powershell
python -m unittest discover -s tests -p "test_article_title*.py"
node --test tests/article_titles.test.js
node --check static/js/article_titles.js
node --check static/js/clipping_service.js
```

모든 단위/통합 테스트의 외부 요청은 모의 응답을 사용한다. 서명 위변조/만료/인증/다른 출처 거부, 모든 카드의 버튼 표시와 미지원 카드의 무요청 안내, 말줄임표 없는 제목 비교와 SEO 부가 문구 배제, 동일 요청 공유/동시 상한, 압축 응답 제한과 내부망 차단, 기본 제목 보존/선택 적용/해제/실패/재시도/카드 제거/기존 편집 내용 보존을 검증 대상으로 한다.
