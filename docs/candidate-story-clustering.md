# 후보 기사 사건 묶음

후보 기사 사건 묶음은 동일 기사를 삭제하는 기능이 아니다. 서로 다른 언론사의 개별 기사를 모두 보존하면서, 같은 사건을 다룬 후보를 하나의 검토 단위로 접어 보여주는 기능이다.

## 처리 순서

1. 원문 URL이 같은 기사는 기존 후보 한 건에 검색어만 누적한다.
2. 최종본 학습 기준으로 후보 적합도 점수를 계산하고 기준점 이상인 기사만 저장한다.
3. 후보 수집이 끝나면 대기 후보의 제목, 요약문, 발행 시각을 비교해 사건 단위로 묶는다.
4. 각 묶음에서 대표 기사를 선정하고 나머지는 `관련 보도`로 표시한다.

## 자동 묶음 기준

- 제목 핵심어 유사도
- 제목의 글자 단위 유사도
- 기사 요약문 유사도
- 공통 핵심어 개수
- 발행 시각 차이 48시간 이내

일반적인 단어 한두 개만 공유하는 기사는 묶지 않는다. 동일한 제목이라도 발행 시각이 48시간을 초과하면 반복 이슈일 가능성이 있으므로 별도 사건으로 유지한다.

## 대표 기사

대표 기사는 다음 정보를 조합해 자동 선정한다.

- 최종본 학습 이력에서 자주 선택된 언론사
- 후보 적합도 점수
- 묶음 내 다른 기사와의 평균 유사도
- 기사 요약문의 충실도
- 최초 보도 시각

사용자가 `대표로 지정`을 선택하면 자동 선정 결과보다 사용자 지정을 우선한다.

## 후보 상태

- `pending`: 검토 대기 중인 후보
- `accepted`: 클리핑 탭에 반영한 대표 기사
- `covered`: 대표 기사와 같은 사건으로 검토가 완료된 관련 보도. 부정 학습에 사용하지 않는다.
- `rejected`: 내용이 부적합하다고 명시적으로 제외한 기사. 이후 후보 감점 근거로 사용한다.

대표 기사를 반영한 뒤 관련 보도를 다시 검토해야 하면 `대기 후보로 복원`할 수 있다.

## 저장과 복원

사건 그룹 키, 대표 여부, 대표 기사와의 유사도, 사용자 대표 지정, 묶음 제외 상태는 `clipping_candidates` 테이블에 저장된다. 이 테이블은 기존 GitHub 스토리지 백업 대상이므로 최종본 학습 후 생성되는 백업 스냅샷에도 함께 포함된다.

기존 백업에는 새 군집 열이 없을 수 있다. 복원 시 기본값으로 가져온 뒤 대기 후보를 다시 군집화하므로 기존 학습 데이터 및 후보 데이터와 호환된다.

이 기능을 위해 운영자가 추가로 설정해야 하는 환경변수는 없다.
