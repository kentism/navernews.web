# 학습 탭 기능

학습 탭은 최종본 학습 이력, GitHub 백업 상태, 후보 수집 검색어, 후보 기사 목록을 한 화면에서 관리한다.

## 최종본 학습 이력

- 클리핑 탭에서 완성한 최종본을 학습하면 학습 이력에 저장된다.
- 학습 탭의 이력 조회, 백업 복원, 이력 삭제 기능은 관리자 비밀번호를 입력한 뒤 사용할 수 있다.
- 학습 직후 GitHub 백업이 실행되며, 새 배포 이후 서버 DB가 비어 있을 때 복원 여부를 확인할 수 있다.
- 학습 이력은 후보 선별 기준이 누적되고 있는지 육안으로 확인하기 위한 운영 화면이다.
- 학습 이력을 수정하면 해당 최종본의 내용과 기사별 학습 이벤트를 다시 구성하고 GitHub 백업을 갱신한다.
- 학습 이력을 삭제하면 해당 행이 먼저 삭제 중 상태로 전환되고, 서버와 GitHub 백업 반영이 끝난 뒤 목록과 요약 정보가 새로고침된다.

## 후보 수집 검색어

- 후보 수집 검색어는 학습 탭에서 직접 추가하거나 제거할 수 있다.
- `현재 열린 검색결과 탭 키워드 일괄 추가` 버튼은 현재 브라우저에 열려 있는 검색결과 탭의 검색어를 읽어 후보 수집 검색어로 등록한다.
- 이미 등록된 검색어는 다시 추가하지 않는다.

## 후보 수집

- 수집 기간은 마지막 학습 시점 이후, 오늘 00시부터, 최근 24시간, 최근 3일 중에서 선택한다.
- 후보 수집은 등록된 후보 수집 검색어를 기준으로 네이버 뉴스 API를 조회한다.
- 같은 URL의 동일 기사가 여러 검색어에서 발견되면 후보 카드는 하나만 유지하고, 검색어 표시에 발견된 검색어를 함께 누적한다.
- 서로 다른 URL이지만 같은 사건을 다룬 기사는 대표 기사 한 건과 `관련 보도 n건`으로 묶는다. 개별 기사는 삭제하지 않는다.
- 관련 보도는 펼쳐서 원문 확인, 개별 클리핑, 부적합 제외, 대표 기사 지정, 묶음 해제를 할 수 있다.
- 자동 묶음이 잘못된 경우 `묶음 해제`를 사용한다. 해제한 기사는 이후 자동 재군집화에서도 독립 후보로 유지되며 `자동 묶음 복원`으로 되돌릴 수 있다.
- 대표 기사를 클리핑하면 같은 묶음의 나머지는 `covered` 상태로 중립 보존된다. 이 상태는 부정 학습에 사용되지 않으며 반영 이력의 관련 보도 목록에서 확인할 수 있다.
- `부적합 제외`한 후보만 이후 후보 점수화에서 유사 기사 감점 근거로 사용된다.
- `대기 후보 비우기`는 아직 검토하지 않은 `pending` 후보만 삭제하며, 제외/반영 이력은 유지한다.
- 후보 목록은 대기 후보, 제외 이력, 반영 이력으로 나누어 확인할 수 있다.
- 제외 이력은 대기 후보로 복원하거나 영구 삭제할 수 있다. 영구 삭제하면 해당 제외 이력은 감점 근거에서도 사라진다.
- 7일이 지난 미검토 후보는 후보 조회 또는 수집 시 자동 정리된다. 제외/반영 이력은 자동 정리 대상이 아니다.
- 점수 사유에 제외 이력 감점이 적용된 후보는 카드 상단 배지와 감점 사유 표시로 구분한다.

사건 묶음의 판정 기준과 저장 방식은 [후보 기사 사건 묶음](candidate-story-clustering.md)을 참고한다.
